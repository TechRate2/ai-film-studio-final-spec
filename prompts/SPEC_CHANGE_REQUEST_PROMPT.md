# Spec Change Request Prompt

Do not implement the proposed canonical change yet.

Produce:
1. concrete problem/evidence;
2. exact affected SPEC_LOCK/canonical clauses;
3. whether change is Class A/B/C;
4. alternatives including preserving current contract;
5. impact on schemas/APIs/jobs/UI/cost/continuity/security;
6. affected tasks/golden scenarios/traceability;
7. migration/backward-compatibility plan;
8. proposed ADR text;
9. explicit owner decision required.

A model/provider limitation should first be handled through profiles/compilers/degrade planning; it is not automatically a reason to weaken the Generalist Director architecture.
