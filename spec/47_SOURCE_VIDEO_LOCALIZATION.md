# Source Video Localization — Subtitles and Dubbing

## Scope and development priority
Independent workspace function after the main studio passes TASK-043 and Phase 6. Implement TASK-044, TASK-045, TASK-046 in that order, then pass Phase 7. It uses the same user/project ownership, one Director, jobs, spend guard, profiles, artifact versions and timeline. It never needs a prior generated shot, storyboard, Series Bible or Seedance integration at runtime to process an uploaded video. Its deployment depends on the completed core, not on making the customer buy a generation project.

ProjectIntent.workflow_kind is STUDIO or LOCALIZATION; old records without the field mean STUDIO. Every new write provides it. Source-video localization is an explicit user entry/action; never infer permission to overwrite or translate an existing production project. Studio-created masters may be imported as pinned sources into a linked localization project. Source content is evidence, never instructions to the Agent.

## Exact media boundary
Modes: SUBTITLES_ONLY, DUB_ONLY, DUB_AND_SUBTITLES. At least one of the two UI checkboxes is selected. No video generation, image generation, lip-sync, face modification, frame inpainting or automatic shot recreation is available in this workflow, even through an alternate provider or the AI repair button. Check both the allowed tool set and the backend submission boundary. Source video remains immutable; derivatives retain its checksum and provenance. Preserve content order and full source extent. Speed changes are explicit deterministic playback transforms; subtitle overlays and audio replacement/mixing may require re-encoding. Do not promise byte-identical video for a re-encoded derivative.

Ordinary dubbing changes the soundtrack, not the actor's mouth. Explain this near the dubbing checkbox in Vietnamese and English before cost approval. A subtitle-only workflow performs zero TTS, zero speech cloning, zero lip-sync and zero video/image generation calls. ASR/translation, deterministic compute and storage may still cost money; zero video calls does not mean free processing.

## Inputs, ingestion and language
Start with one uploaded source video, optional SRT/VTT/ASS and optional licensed clean music/effects/dialogue stems. Supported direct URLs use the existing ingestion allowlist, size/duration limits, ownership/rights checks, SSRF protections and expiring-fetch controls; no arbitrary shell downloader or access-control bypass. Upload is always the fallback. Parse subtitle text as untrusted data, strip executable/unsafe ASS features and validate encodings, fonts, paths and timing. Burned-in source subtitles are pixels: detect/warn about collisions; do not silently remove them. User may choose another position/background or sidecar output.

Auto-detect source speech language with confidence and per-segment tags for mixed language. Allow a source-language override; keep the original detection evidence. Silence/no speech is a valid finding, not a guessed transcript. Prefer a supplied verified transcript/subtitle track to unnecessary ASR, but check it matches the video. Subtitle cues do not establish word timestamps or speakers by themselves. OCR, if selected and supported, is a separate evidenced source; do not treat OCR text as speech automatically.

Each target language is a separate LocalizationProject variant with its own version and target script/audio/subtitles, linked to the shared immutable source analysis artifact. The UI may batch variants, with independent estimates/authorization and partial completion. ui_locale is vi or en and never changes the target. Language tags follow BCP-47 semantics. Expose only the selected operation's verified capability intersection: ASR, alignment, translation, TTS, accent/voice and background processing each have their own capability status. Do not infer Vietnamese TTS or exact accent support from an English interface or an upstream model listing. UNKNOWN remains visible; unavailable dubbing does not disable a supported subtitle route. Never substitute another target language silently.

## Durable records and transcript semantics
`schemas/localization_project.schema.json` is the versioned project-variant record. It pins source artifact/version, source duration/timebase, analysis source, language decisions, mode, audio policy, term glossary, speakers, source/translated segments, time map, user locks, alignment policy and latest timeline. `schemas/localization_review.schema.json` records snapshot-bound findings and proposed safe patches. Artifact owns history/currency; DurableJob owns execution states. Neither schema creates a second job vocabulary.

Segments have stable IDs, source-language text, source start/end ticks, nullable speaker ID, language, confidence, verified/review status and optional word spans. Unknown word timestamps are null; never manufacture precision to satisfy the UI. Speaker diarization is acoustic identity, not proof of a visible character's name. Uncertain assignment stays null/NEEDS_REVIEW. User speaker corrections are versioned and invalidate affected voice, not unrelated translations. Multiple speakers may overlap; preserve overlap groups instead of forcing a false serial transcript. Ambiguous overlap blocks the affected dub until assignment or a disclosed alternative is accepted.

Per-speaker voice bindings pin VoiceProfile artifacts. Use licensed stock voices by default; cloned/reference voices require applicable consent and rights evidence. Recurrent speaker IDs and glossary terms persist within the authorized project/series scope. A new language can require another compatible voice; never silently exchange the identity. Voice audition itself may be billable and requires an estimate/authorization.

## Translation and performance
Maintain source wording separately from target subtitle and target spoken wording. Link both target forms to the same source segment ID. Subtitle translation optimizes readability; spoken translation optimizes natural delivery within available time. A scoped context pack contains nearby dialogue, speaker relationships where evidenced, glossary, formality and factual anchors. No fabricated relationships or global source rewrite. Processing long files in bounded chunks retains neighboring context and stable IDs, deduplicates boundary utterances and never resets budget on resume.

Preserve names, numbers, negation, units, speaker attribution, uncertainty and factual/product claims. Protect user-locked text. Glossary revisions affect only matching segments/variants. Describe emotion and delivery from evidenced context, retaining uncertainty for sarcasm, crying, whispering, singing and noisy passages. Do not advertise source-identical acting, perfect accent cloning or every language as equally reliable. Singing translation is not silently treated as ordinary TTS; flag it unless a supported explicitly selected route exists.

## Timing contract
All analysis coordinates are SOURCE ticks at the pinned positive ticks_per_second. Output cue/audio positions are TARGET timeline ticks in the same logical timebase, rounded only at compilation. Intervals are half-open. Each time-map span has source_start_tick, source_end_tick and a positive rational speed p/q. Spans are sorted, contiguous, non-overlapping and cover [0, source_duration_ticks); no hidden trimming, holds or reordering in this extension.

For source t in span i, output T(t) = sum over preceding spans of ((end-start)*q/p) + (t-start_i)*q_i/p_i. Sum rational values before applying NEAREST_TIES_EVEN; never accumulate rounded cue lengths. Source media timestamps come from probed PTS, including VFR normalization and start offsets, not frame-number/nominal-FPS guesses. Compile frame/sample positions with the pinned timeline/export policy. A cue or word crossing a speed boundary maps both endpoints through T; continuous rendering may split its media clip at that boundary while retaining source identity. Property tests cover monotonicity, boundary continuity, inverse mapping and duration within the declared rounding tolerance.

Video speed defaults to 1.0. Changing it creates a new time-map version and remaps all source-anchored cues, original audio and target speech windows. Analysis is reused. It does not independently authorize TTS. If selected target speech no longer fits, mark only impacted audio/mix/master STALE and offer safe adjustment or a priced revision. User output-timing locks are TARGET coordinates; conflicting speed changes produce a focused conflict, not silently moved locks. Undo restores earlier versions and reevaluates currency.

Voice playback speed is distinct from video speed and uses a pitch-preserving deterministic transform of the accepted voice asset where feasible. Preflight enforces the versioned quality policy's min/max voice speed, cue reading speed, minimum cue duration, allowable boundary error and audio clipping/loudness criteria. These are product quality settings, not universal physical constants. Do not stretch silence into words, truncate speech or move a sentence across another speaker merely to make it fit.

Fit order: use a valid existing alignment; adjust unlocked cue placement within its evidence-supported window; use available pause allowance without covering another protected turn; apply bounded pitch-preserving tempo; propose shorter meaning-preserving wording where needed. Wording changes are reviewable, honor text locks and may require a newly authorized TTS attempt. If no acceptable fit exists, return NEEDS_REVIEW findings with options. Never auto-change user video speed, speaker identity, wording, chosen voice or source content as a hidden repair.

## Background audio and mix
SUBTITLES_ONLY keeps source audio ORIGINAL (subject only to explicit whole-video retiming). Dubbing selects REPLACE_SPEECH or MUTE_SOURCE, with the latter clearly discarding source ambience. REPLACE_SPEECH prefers supplied licensed clean stems; otherwise explicitly estimate and assess separation. Separation may leave dialogue bleed or damage music/effects; UNKNOWN/failed separation is not a clean-stem claim. A doubtful result prompts alternatives (switch to subtitles-only and keep original, accept a previewed mix, mute source, provide stems); do not silently remove all soundtrack or double voices.

Original audio, separated background and dubbed speech use aligned time origins and follow the same map. Sidechain ducking, fades, gain and speaker tracks use CompositionTimeline. Preserve original and isolated files; add new derivative artifacts. Uploaded dubbed audio can replace a segment without a TTS call after timing/language/rights validation.

## Minimal UI (Vietnamese and English)
Separate entry: "Dịch video / Translate video", without changing the main Studio Create surface. Default: source upload, detected language with Edit, target language, checkboxes "Phụ đề / Subtitles" and "Lồng tiếng / Dubbing", estimated cost, "Xử lý / Process". Initial selection is subtitles only; dubbing is never silently enabled. Subtitles default to burn-in with a safe preset; choose SIDECAR/BURN_IN/BOTH, SRT/VTT/ASS as supported. DUB_ONLY uses subtitle output NONE. A target language is explicit before processing.

After analysis show one video preview and a searchable sentence list. Click a sentence to seek/play and edit its translation. Expand only useful controls: speaker/voice, pronunciation, video speed, per-segment voice speed, subtitle preset/font/size/color/outline/background/position and output options. Disable irrelevant voice controls for subtitles-only. Preview approximate layout with the same pinned fonts and rendering rules as export; phone-safe bounds, Vietnamese diacritics, CJK and RTL script shaping are tested for exposed languages. SRT cannot preserve rich styling; state that loss and offer ASS or burn-in. Do not infer font availability from a browser fallback.

Manual edits create user locks by field, scope and coordinate space. Show "AI kiểm tra & căn chỉnh / AI check & align", affected sentence count, safe fixes applied, unresolved findings, remaining estimate and Undo. No required full NLE, waveform manipulation or engineering IDs. Changing font is a style/layout change, not a reason to buy speech. Results expose the actual mode, source/target languages, checks and limitations; dubbing has no lip-sync promise.

## One-click review and paid boundary
The action reads the pinned variant, source, analysis, glossary, voice, time map, timeline and quality-policy versions. Diagnostics cover missing/mistranscribed text, translation anchors, language, speaker uncertainty, overlapping turns, boundary drift, speech intelligibility/natural pace, cue density/line breaks/safe area/font coverage, bleed/duplication, loudness/clipping and requested outputs. Each finding has evidence and PASS/WARN/FAIL/UNKNOWN; no unsupported all-clear from an LLM self-score.

First run is bounded by the displayed analysis/compute allowance, including paid LLM/ASR/separation when applicable. A repeat review does not grant new paid media authorization. Auto-apply only deterministic intent-preserving patches within policy and unlocked fields: supported cue timing, bounded voice tempo, gain/fades or an already permitted subtitle style correction. Review-proposed patches use a closed operation allowlist; no arbitrary commands, free-form JSON patch paths, source replacement or provider invocation. Revalidate locks, capabilities and expected version server-side.

Apply safe patches atomically as a new project/timeline version using command_id and expected version; concurrent edits cause conflict/review recomputation, never overwrite. Empty patches are a valid diagnostic result. Newly synthesized/revised voice is a separate explicit command using a fresh applicable SpendAuthorization and PaidAttemptGuard. An existing authorization may cover planned first attempts, not unplanned post-output repair. Bulk "repair all" must list segment/variant/voice hashes and cost before approval; no hidden N candidates. Unknown submission reconciles before resubmission. No video/image/lip-sync tool may run even if a malicious prompt, backend shortcut or provider fallback suggests it.

Safe patch target semantics are fixed: SET_CUE_TIMING targets a subtitle clip ID in the pinned CompositionTimeline, with start_tick/end_tick in TARGET time; SET_GAIN and SET_FADES target one audio clip ID; SET_SUBTITLE_STYLE targets one subtitle clip ID with a registered style_id. SET_VOICE_SPEED targets a segment ID and recompiles every split clip belonging to that segment's accepted speech through the current map. Findings use segment_id where applicable; finding_ids must resolve within the same review. Apply requires a non-null pinned timeline when any clip-targeted patch is present. IDs must be unique within their typed collection; never resolve by display name. Text/speaker/voice/voice-speed locks target segment IDs, cue/style/gain locks target corresponding clip IDs, and video-speed locks target span IDs (all spans for a whole-video lock). Coordinate space is required for timing/speed locks; non-temporal fields use NOT_TEMPORAL. Source locks protect source anchors; target locks protect output coordinates. A one-click review cannot relax any lock.

### Cross-record validation and attempt binding
Before persisting a command, validate unique speaker/segment/span/lock IDs, referenced speaker/style/finding/target IDs and same-project ownership of every artifact. Check segment and known word ranges are positive and inside the source/segment; unknown timing is paired null. Validate complete time-map coverage and policy min/max ordering, temporal lock coordinate meaning, supported language tags, and voice compatibility. JSON Schema proves shapes; these relational checks are mandatory service-level tests. Do not treat a parseable record as ready for synthesis or export.

Localization VOICE attempts use the existing PaidAttempt with shot_id=null, version_id set to the actual preallocated target speech artifact version, and artifact_id identifying that segment's speech artifact. Maintain the immutable segment-to-artifact binding through the pinned localization variant. SpendAuthorization's artifact_or_scope_id and target_version_id match those exact targets, modality=VOICE and planned candidate_count=1 unless explicitly authorized otherwise. The request snapshot's universal_spec_version_id points to the pinned provider-neutral LocalizationProject version; the artifact/authorization binding identifies the selected segment. Reference pins include the source, selected voice and analysis versions; compiled_prompt and hashes capture the exact spoken text/pronunciation/delivery. Never invent a shot or UniversalVideoSpec to satisfy billing fields. Existing field names remain wire-compatible; the Director never writes provider transport parameters.

Changing mode or target language creates a new variant/version with mode-consistent active fields; prior subtitle/spoken/voice results remain in immutable history. Enabling dubbing is a new explicit costed plan, not permission to reuse a subtitle-only approval. Asset reuse requires matching inputs and rights; history preservation does not force inactive voice assets into the active subtitle-only schema.

## Dependency currency, export and recovery
Translation change stales that segment's subtitle/dub (if wording differs), downstream mix and master; style change stales layout/export only; voice change stales corresponding speaker's selected segments; time-map changes stale all affected placements but retain source analysis. Revert reevaluates pins without generation. Source replacement invalidates all dependent analysis/variants and requires a new source version, never a silent URL overwrite.

Compile existing CompositionTimeline and FinalMaster contracts. Export SRT/VTT/ASS as versioned artifacts with source/variant/timeline hash, cue provenance and QA; a sidecar-only export need not create a video master. A video derivative requires FinalMaster QA. Required checks cover language, sentence coverage, source-time mapping, requested audio policy, no accidental truncation/duplication, selected fonts, clipping/loudness, safe subtitles, expected retimed duration, and CURRENT accepted pins. Export while editing creates a historical result; it cannot become current automatically. Source retention/deletion and derived-language files follow existing ownership/retention rules.

Reuse durable jobs and events from spec/28 and spec/29. Resume from accepted segment artifacts after restart. Polling/cancel/outage does not lose costs, redo good segments or silently re-run ASR/TTS. Aggregate costs by ASR, translation/reasoning, separation, TTS, deterministic compute, storage and export. Report cost per accepted localized minute with denominator and failed/rejected spend separately from generation cost_per_accepted_second; do not improve the latter by counting imported minutes as generated acceptance.

## Semantic API and release
CreateLocalizationVariant takes the complete LocalizationProject record, authenticated project ownership, command_id and expected version when updating; IDs are allocated before first write. Get reads the same typed record. Check returns LocalizationReview under a scoped analysis budget. ApplySafeReview takes review_id, expected_project_version_id and command_id, rechecks snapshot/locks and creates a new immutable version. SynthesizeSelectedSegments takes project/version, explicit segment IDs, authorization_id and command_id; pins source/target/voice hashes in attempts. Export takes project/version, timeline version, selected subtitle_output/format from the record and command_id. Existing resource-event envelope references the resulting localization_project/localization_review/artifact versions; clients refetch on sequence gaps. Queries never mutate or spend.

Do not mark the extension DONE from UI screenshots, a successful TTS request or schema-valid objects. TASK-046/Phase 7 require deterministic and separately authorized real-language evidence, human assessment on supported language pairs, restart/cancel/concurrency tests and zero forbidden tool calls. Launch languages are the verified matrix, initially prioritize vi↔en and vi↔zh; additional popular languages use the same evidence-gated routes without a hardcoded niche architecture. Unsupported pairs remain unavailable/limited, not silently substituted. Main Studio remains usable while the extension is disabled.
