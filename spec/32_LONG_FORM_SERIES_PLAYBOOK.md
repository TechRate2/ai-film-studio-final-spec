# Long-Form and Series Playbook

## Hierarchy
SERIES/WORLD → CHARACTER/RELATIONSHIP/CANON → EPISODE ARC → SCENE CONTRACT → BLOCKING/DIALOGUE → SHOTS → ACCEPTED OUTPUT STATE.

## Active context
Never send the full series bible to every step. Build an ActiveContextPack from current episode/scene, active characters, relevant facts/relationships/knowledge, current outfits/props/voice, unresolved thread relevance and recent accepted continuity.

## Canon vs mutable state
Canonical identity/default appearance/voice/world rules are stable. Episode/scene state is mutable. Shot state is transient. Accepted real outputs update observed continuity but never silently rewrite canonical identity.

## Character knowledge safety
Before dialogue/action, resolve what each character knows, believes, suspects or misunderstands at this point. Audience/world knowledge does not automatically become character knowledge.

## Episode commit
After episode acceptance create a canon snapshot/diff with plot facts, relationship changes, character knowledge changes, outfit/injury/prop/location state, unresolved hooks, voice/pronunciation state and last accepted continuity assets.

## Retcons
User changes create new canon versions. Dependency graph marks affected downstream artifacts stale. Do not erase historical episode/version provenance or auto-regenerate paid media.

## Many characters
A project may maintain 5–10+ recurring characters. A single shot should include only the cast necessary for readable storytelling/model reliability. Complex crowds/battles are decomposed into geography, hero actions and reactions without turning every extra into a persistent entity.

## Series acceptance
A later episode must resume without requiring the user to re-upload canonical refs unless the asset is missing/invalidated or user requests replacement.

## ActiveContextPack validity
Each pack has its own ID/version, retrieval purpose, project/canon versions, story position, role-specific knowledge refs, source version pins, token budget and omitted-context summary. Retrieve by active entities, causal relevance and required incoming/outgoing continuity, not transcript recency alone. Mandatory hard facts/locks/knowledge cannot be silently truncated to fit budget: reduce optional context, retrieve more narrowly or block. Revalidate pins before planning commit, paid submission and acceptance. Pack construction supports 10+ registered characters with a small active subset and paginated retrieval, including cross-episode props and unresolved promises.
